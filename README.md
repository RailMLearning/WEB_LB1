# Лабораторная №2

Запуск из корня проекта:

```sh
python -m pip install -r requirements.txt
python -m uvicorn server.routers.serve:app --host 127.0.0.1 --port 8000
```

Страница: http://127.0.0.1:8000/

Данные хранятся списком в `server/db.json`. Переменная окружения `DB_PATH` позволяет выбрать другой файл.

Запуск через Docker Desktop:

```sh
docker compose up --build -d
docker compose down
```

Перед запуском Docker остановите локальный сервер на порту 8000. В контейнере используется отдельное хранилище `/data/db.json`, первоначально пустое. Именованный том `students` сохраняет записи после пересоздания контейнера.

Создание, редактирование, удаление и чтение выполняются через `fetch`. Cookies для данных студентов не используются.

`GET /api/requests` возвращает список. Фильтры: `isu`, `fio`, `group` (или `grid`), `dormitory` (или `dnum`), `rnum`, `expdate`, `foreigner`, `notes`. ФИО и заметки ищутся по подстроке без учёта регистра; остальные поля сравниваются точно. Все фильтры применяются одновременно.

Пример: `/api/requests?group=M3301&dormitory=8`.

`QUERY /api/requests` принимает те же фильтры JSON-объектом в теле запроса. Интерфейс использует QUERY при заполнении более трёх фильтров; это выбранный для лабораторной порог. Метод проверяется через интерфейс или HTTP-клиент, в Swagger не отображается.

`POST /api/requests` создаёт студента, `PATCH /api/requests/{isu}` обновляет переданные поля, `DELETE /api/requests/{isu}` удаляет запись, `GET /api/requests/{isu}` открывает досье.

Ошибки имеют формат `{"detail": [{"field": "isu", "message": "Сообщение"}]}`. Для общей ошибки `field` равен `null`. Используется один процесс Uvicorn для JSON-хранилища.

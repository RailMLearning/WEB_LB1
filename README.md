# Лабораторная №4: Vue, Pinia и RxJS

Frontend системы учёта студентов общежития. Вариант — Vue 3. Приложение обращается к Java API
третьей лабораторной: Jakarta EE / Hibernate, PostgreSQL, access- и refresh-токены.

## Запуск в Docker

Нужны Docker с Linux-контейнерами и Docker Compose. Для создания конфигурации можно использовать
Node.js 22.12+ или 24:

```bash
npm run setup
docker compose up --build
```

`npm run setup` создаёт локальный `.env` со случайными секретами и не перезаписывает существующий.
Вместо скрипта можно скопировать `.env.example` в `.env` и заполнить значения самостоятельно. В
Windows также доступен `tools/setup-env.ps1`.

- Приложение: http://127.0.0.1:8080/
- Вход: http://127.0.0.1:8080/login
- Регистрация: http://127.0.0.1:8080/register
- Профиль: http://127.0.0.1:8080/profile
- Swagger UI: http://127.0.0.1:8080/docs
- Проверка Java API: http://127.0.0.1:8000/api/health

Администратор создаётся из `ADMIN_USERNAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` при первом запуске.
Учётные данные находятся только в локальном `.env`. Новый пользователь, зарегистрированный через
страницу, получает роль USER и доступ к просмотру.

`ADMIN_PASSWORD`: минимум 8 символов, максимум 72 байта UTF-8. `JWT_SECRET`: минимум 32 байта.
`DB_PASSWORD` обязателен. Порты на компьютере задаются `API_PORT` и `FRONTEND_PORT`.

```bash
docker compose up --build -d
docker compose ps
docker compose logs -f web frontend
docker compose down
```

`down` сохраняет PostgreSQL-том. Не используйте `down -v`, если нужно сохранить данные. Flyway
запускается после готовности БД; Java — после успешных миграций; Nginx — после готовности API. На
существующей БД используется настроенный baseline миграций третьей лабы. Изменение `ADMIN_PASSWORD`
в `.env` не меняет пароль уже созданного администратора.

## Возможности

- Список, карточка студента, создание, редактирование и подтверждение удаления.
- Поиск, фильтры по всем восьми полям, сортировка по всем полям и серверная пагинация.
- Вход, регистрация, выход, профиль и восстановление сеанса после обновления страницы.
- Защищённые маршруты. USER читает записи; ADMIN также изменяет их.
- Автоматическое обновление JWT. Одновременные 401 используют один refresh-запрос.
- Проверка полей, понятные ошибки, загрузка, блокировка повторной отправки форм.
- Работа без перезагрузки документа, адаптация к мобильному экрану.

Поиск срабатывает через 300 мс после ввода. RxJS отменяет предыдущий запрос через AbortController и
не показывает устаревший результат. Уход со страницы снимает подписку и отменяет текущую загрузку.
При более чем трёх непустых фильтрах используется QUERY с JSON-телом; иначе GET с query-параметрами.
Сортировка и параметры страницы не считаются поисковыми фильтрами.

## Структура frontend

```text
frontend/
  src/
    components/       повторно используемые формы, таблица, фильтры и диалог
    views/            страницы маршрутов
    stores/           глобальные состояния Pinia: auth и students
    services/         API-клиент, RxJS-поток, запросы и валидация
    router.js         маршруты и проверка доступа
    App.vue           общий интерфейс и реакция на завершение сеанса
    main.js           подключение Vue, Pinia и Router
    styles.css        общие стили и мобильный интерфейс
  nginx/              шаблон конфигурации Nginx
  public/             статические ресурсы
vite.config.js       сборка и прокси API для разработки
```

Старые `static`, `templates`, `server.cjs` сохранены как реализация предыдущей лабы и не входят в
сборку нового интерфейса. Сведения о Java API — `README_LAB3.md`, `LAB3_REPORT.md` и OpenAPI.

## Разработка без сборки frontend-контейнера

```bash
npm ci
npm run setup
docker compose up --build -d db migrate web
npm run dev
```

Vite открывается на http://127.0.0.1:5173/. Запросы `/api` проксируются на `DEV_API_TARGET` из
локального `.env` (по умолчанию http://127.0.0.1:8000). Секреты `.env` не включаются в
JavaScript-сборку. Клиент использует относительный `/api`, поэтому ручная настройка CORS не нужна.

В Docker первая стадия `Dockerfile.frontend` собирает Vue через Vite, вторая содержит Nginx и
готовые файлы `dist`. Node и исходники приложения не нужны в конечном контейнере. Nginx возвращает
`index.html` для клиентских маршрутов и проксирует `/api` в Java. `BACKEND_HOST` и `BACKEND_PORT`
задаются окружением frontend-контейнера при запуске.

## Проверки

```bash
npm test
npm run build
npm run test:ui
```

`npm test`: тесты API-клиента, конкурентного refresh, RxJS, отмены запросов и валидации.
`npm run test:ui`: браузерный сценарий с настоящим API. В Windows используется установленный Edge,
если не задан `BROWSER_PATH`. Для другого компьютера можно установить Chromium:

```bash
npx playwright install chromium
```

Браузерный тест использует `LAB4_URL` (по умолчанию http://127.0.0.1:8080), создаёт свои записи
студентов и удаляет их после проверки. Тестовый USER остаётся в БД. Снимки экрана сохраняются в
игнорируемой папке `test-results`.

Для проверок Java API сохранены `npm run test:api` и Postman-коллекция
`api/lab3.postman_collection.json`. Прежний браузерный тест доступен как `npm run test:ui:lab3` и
рассчитан на старый Node-интерфейс, а не на Vue.

- `LAB4_REPORT.md`: реализация требований и результаты проверок.
- `LAB4_DEFENSE.md`: ответы на 20 вопросов с указанием файлов проекта.
- `LAB4_REVIEW.md`: проверенные сценарии и ограничения.
- `CHANGELOG.md`: изменения относительно третьей лабы.

Токены хранятся в sessionStorage текущей вкладки. Пароли и токены не выводятся в интерфейс, профиль
или журнал. Logout отзывает refresh; выданный access действует до своего expiration. Для публикации
за пределами локального компьютера нужно настроить HTTPS.

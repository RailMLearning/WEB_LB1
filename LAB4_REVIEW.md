## Результаты

- Unit-тесты frontend: 14 проверок прошли.
- Production-сборка Vite: выполнена.
- Docker: frontend собирается в две стадии; Nginx, Java и PostgreSQL находятся в `healthy`, миграции
  завершаются с кодом 0.
- HTTP API: 68 проверок прошли через Nginx-прокси. Проверяются операции студентов, роли, валидация,
  QUERY, конкурентные INSERT, ротация refresh и формат ответов.
- Браузер: пройдены CRUD, все фильтры, QUERY, сортировка, две страницы результатов, профили
  ADMIN/USER, реальное обновление JWT, ограничения USER, отзыв refresh и возврат на вход.
- Ошибки: проверены недоступность сети, ответ 500, повтор запроса и отсутствие студента.
- Маршруты: проверены прямое открытие и перезагрузка вложенного адреса, страницы 403/404 и Swagger.
- Мобильный экран 390×844: общая страница не имеет горизонтального переполнения; широкая таблица
  прокручивается внутри собственного контейнера.

## Найденные при совместном запуске проблемы

- У стартового EJB был только конструктор с зависимостью, а сервер требует public no-args. Для него
  используется внедрение поля; конструктор без аргументов создаётся неявно.
- Stateless CDI-сервисы с final-полями и constructor injection не могли получить normal-scope client
  proxy. Для них выбран `@Dependent`, constructor injection сохранён.
- JAX-RS resources и provider должны создаваться совместимым с RESTEasy способом; они используют
  внедрение полей и неявный пустой конструктор.
- RESTEasy не предоставлял ContainerRequestContext методу `/auth/me`. Профиль читает сохранённый
  фильтром атрибут через HttpServletRequest.
- Скрытая подпись колонки могла расширять мобильную страницу за пределы таблицы. Контейнер прокрутки
  таблицы получил `position: relative`.
- Стандартный JSON-reader авторизации возвращал HTML при неизвестном поле. `AuthRequestReader`
  сохраняет DTO на входе и использует общий валидатор и формат ошибок.
- Проверка Location допускала только относительный адрес старого Node-прокси. Теперь тест
  нормализует URI и проверяет публичный адрес ресурса; абсолютный публичный URL Nginx допустим.

## Ограничения

- Токены в sessionStorage доступны скриптам вкладки. HttpOnly-cookie и серверное управление
  устройствами не реализованы. Logout отзывает refresh, но access действует до expiration.
- JWT_SECRET, DB_PASSWORD и ADMIN_PASSWORD не имеют общих значений для всех установок: перед первым
  запуском нужно создать `.env` скриптом или по образцу.
- Swagger загружается отдельным крупным модулем только при открытии `/docs`. Предупреждение Vite о
  размере этого модуля не означает ошибку сборки основного интерфейса.
- Состояние Pinia сохраняется между переходами; фильтры списка не сохраняются после полного
  обновления документа. Сеанс сохраняется в рамках вкладки.
- Браузерные проверки удаляют только созданных ими студентов. Тестовый пользователь остаётся в БД,
  потому что публичного API удаления пользователей в лабораторной нет.
- Длительные нагрузочные проверки и проверка всех браузеров не выполнялись.

Основание решения проблемы CDI:
[документация Weld о client proxies](https://docs.jboss.org/weld/reference/latest/en-US/html/injection.html).

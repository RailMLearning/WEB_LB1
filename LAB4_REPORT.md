# Отчёт по лабораторной работе №4

Вариант: Vue. Дата проверки: 10.11.2026.

## Цель

Перенести интерфейс учёта студентов на JavaScript-фреймворк, сохранив работу с Java REST API третьей
лабораторной. Добавить компонентную архитектуру, маршрутизацию, глобальное состояние и практическое
применение RxJS.

## Технологии

- Vue 3 и Single-File Components с Composition API и `<script setup>`.
- Vue Router: маршруты страниц, параметры ИСУ и проверка доступа.
- Pinia: хранилища авторизации и списка студентов.
- RxJS: потоки поисковых условий, задержка ввода, переключение и отмена запросов.
- Vite: сервер разработки и production-сборка.
- Nginx: раздача сборки, SPA fallback и проксирование API.
- Backend: Jakarta EE / Hibernate, PostgreSQL, Flyway и JWT из третьей лабораторной.

Версии зависимостей закреплены в `package.json` и `package-lock.json`.

## Архитектура

```text
Vue-компоненты → Pinia → services → /api → Nginx → WildFly → PostgreSQL
                        ↑
                поток поиска RxJS
```

`views` отвечают за страницы, `components` — за повторно используемые части интерфейса. Формы
получают начальные данные через props и передают результат событием `submit`. Локальное состояние
хранит введённые поля, ошибки и выполнение операции. Pinia сохраняет сеанс, текущего пользователя,
условия поиска, страницу и результаты списка.

API-клиент, проверка полей и реактивная загрузка отделены от шаблонов компонентов. Старые `static` и
`templates` сохранены, но не используются в production-сборке Vue.

## Страницы и права

| Маршрут               | Назначение                       |
| --------------------- | -------------------------------- |
| `/login`              | Вход                             |
| `/register`           | Регистрация                      |
| `/profile`            | Профиль текущего пользователя    |
| `/students`           | Список, поиск и фильтры          |
| `/students/new`       | Создание, только ADMIN           |
| `/students/:isu`      | Карточка студента                |
| `/students/:isu/edit` | Редактирование, только ADMIN     |
| `/forbidden`          | Сообщение о недостаточных правах |
| `/docs`               | Swagger UI                       |

Неизвестные адреса показывают страницу 404. Глобальный guard ожидает восстановления сеанса,
перенаправляет гостя на вход и не допускает USER к изменяющим страницам. После входа пользователь
возвращается на внутренний адрес, который собирался открыть. Внешние redirect-адреса отклоняются.

Кнопки изменения скрыты для USER. Окончательная проверка роли остаётся на Java backend: подмена
состояния браузера не даёт права изменять записи.

## Студенты

Реализованы список, карточка, создание, редактирование и удаление с подтверждением. Изменения
отображаются средствами Vue без перезагрузки документа.

Доступны поиск и отдельные фильтры по `isu`, `fio`, `grid`, `dnum`, `rnum`, `expdate`, `foreigner`,
`notes`. Поиск, сортировка и пагинация выполняются API. Метаданные списка читаются из
`X-Total-Count`. Для более трёх непустых фильтров используется QUERY; иначе GET.

Сортировать можно по всем восьми полям, в обоих направлениях. Размер страницы: 10, 20, 50 или 100.
После удаления последней записи страницы номер корректируется по общему количеству записей.

## RxJS

Реактивная логика находится в `frontend/src/services/studentSearch.js` и не зависит от Vue.

1. `BehaviorSubject` хранит последнее состояние условий поиска.
2. `debounceTime(300)` объединяет события быстрого набора.
3. `distinctUntilChanged` пропускает повтор одинаковых условий.
4. Внешний `switchMap` переключается на новые условия.
5. `Subject` позволяет явно повторить загрузку текущего поиска.
6. Внутренний `switchMap` переключает повторные загрузки.
7. `Observable` создаёт запрос и возвращает функцию отмены через `AbortController`.
8. `map`, `startWith` и `catchError` формируют данные, загрузку и ошибку.
9. `shareReplay` разделяет результат между подписчиками; `refCount` отключает источник при
   отсутствии подписчиков.

`StudentsView` подключается к потоку при монтировании и снимает подписку при размонтировании. Ошибка
отдельного запроса не завершает весь поисковый поток: доступна повторная попытка.

## Авторизация

Реализованы регистрация, вход, выход и получение профиля через API. Access и refresh сохраняются в
sessionStorage вкладки. При перезагрузке запрашивается `/api/auth/me`.

API-клиент добавляет `Authorization: Bearer`. После 401 выполняется один refresh и один повтор
исходного запроса. Одновременные запросы используют общий Promise обновления. Версия сеанса не
позволяет старому ответу восстановить сеанс после выхода или перезаписать другой вход. 403 не
запускает обновление токена. Отклонённый refresh завершает локальный сеанс.

## Формы и ошибки

Клиент проверяет формат ИСУ, ФИО, группы, положительные безопасные номера, календарную дату, длину
заметок, логин, почту и длину пароля в UTF-8. Однословные имена разрешены, ведущие нули в ИСУ
сохраняются. Серверная проверка остаётся обязательной.

Поля показывают собственные сообщения. Ошибки API отображаются отдельно и связываются с полями по
`detail[].field`. Обрабатываются 401, 403, 404, 409, 422, 500 и недоступность сервера. Для операций
есть индикация загрузки; повторная отправка формы блокируется флагом и disabled.

Vue выводит пользовательские значения как текст. `v-html` не используется. Заметки, содержащие HTML,
отображаются буквально.

## Docker

Первая стадия `Dockerfile.frontend` выполняет `npm ci` и `npm run build` в Node. Вторая содержит
Nginx и `dist`; исходники и Node-зависимости в неё не копируются. Nginx отдаёт `index.html` для
клиентских маршрутов и проксирует `/api` на Java.

Корневой `compose.yaml` подключает общий Compose: БД, миграции, Java и frontend. После создания
`.env` запуск выполняется командой `docker compose up --build`. Секреты не включаются в клиентскую
сборку. Инструкции находятся в README.

## Совместимость Java

При совместном запуске устранены блокеры существующего backend: требования EJB к пустому
конструктору и ограничения CDI-прокси при constructor injection. В stateless-сервисах сохранён
constructor injection с `@Dependent`; JAX-RS/EJB используют внедрение полей. Транзакционные
аннотации сервисов сохранены.

Профиль читает атрибут пользователя через `HttpServletRequest`: RESTEasy не предоставлял
`ContainerRequestContext` как параметр метода ресурса. Формат REST API не изменён.

`AuthRequestReader` разбирает JSON авторизации в DTO через существующий валидатор. Неизвестные поля,
неверные типы и некорректный JSON возвращают общий формат `detail`, а не HTML-ответ стандартного
JSON-провайдера. Размер читаемого тела ограничен 16 КиБ.

находится в `tools/check-lab4-ui.cjs`.
